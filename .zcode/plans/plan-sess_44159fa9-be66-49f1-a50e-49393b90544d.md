# 方案:设备实时连接查看 + 一键/批量学为自定义特征

## 目标

在 LuCI「特征库」页新增「设备连接」Tab:选择设备 → 实时查看该设备的网络连接(五元组 + 识别到的应用 + SNI/Host)→ 把连接**学成特征**,支持三种玩法:
1. 单条连接 → 新建一个自定义应用(该连接成为它的特征);
2. 单条连接 → **追加到已有自定义应用**(该应用可不断积累多种特征);
3. **多选多条连接 → 批量归入同一个应用**(新建或已有)。

学成的特征自动出现在「自定义应用」Tab 和拦截规则的应用选择器里。完全复用现有自定义应用机制(域名/端口特征,不动内核、不动 ACL)。

## 现状依据(已调研确认)

- `set_custom_feature` 为整表 JSON 提交:每应用 `{class_id, name, features:[{protocol, dest_port, domain, uri, payload}]}`,appid 可省略由服务端自动分配(class×1000+900~999),写 `/etc/fwxd/custom_feature.cfg` → `reload_feature()` → netlink 下发内核 → 出现在应用选择器(`fwx_ubus.c:8577-8579`、`fwx_custom_feature.c:570-648`)。**追加特征 = 前端合并后整表提交,后端无需写接口**。
- 每应用最多 16 条特征、名称全局唯一、域名字段 ≤31 字符(服务端校验,错误信息会透出)。
- 特征匹配三通道:HTTPS SNI + HTTP Host + DNS 查询;空 dport = 匹配任意端口。
- 所有 api 走 `fwx` ubus 对象唯一方法 `common`,新增 api 无需改 ACL。
- 连接数据:容器 netns 的 `/proc/net/nf_conntrack` 有实时五元组,oaf 的 conntrack mark 可解码 appid(低 16 位;drop 位 0x80000000);SNI/Host 用 `/proc/net/af_active_host`(已有解析代码 `fwx_ubus.c:6119`)按目标 IP+端口 join。
- 缺口:仅缺"按设备列连接"的只读 api。

## 实现内容

### 1. oafd 新增只读 api(C,open-app-filter/src/fwx_ubus.c)

新增 `fwx_api_get_dev_conn_list`,注册进 `fwx_api_node_list[]`:

- 入参:`{"ip":"10.10.10.100"}`,可选 `include_lan:0/1`(默认排除内网目标,只看公网方向);
- 解析 `/proc/net/nf_conntrack`:过滤 `src=<ip>`,解码 `mark` 得 app_id/drop,app 名称复用 oafd 现有 app_name_table;抽取 `get_dashboard_active_host`(fwx_ubus.c:6119)的解析为公共函数,按(目标IP,端口,协议)join 出 host;
- 出参:`{code:2000, data:{conntrack_available:1, conn_list:[{proto,dst_ip,dst_port,state,app_id,app_name,host,drop}]}}`,上限 200 行;
- `/proc/net/nf_conntrack` 不存在时返回 `conntrack_available:0`(实施第一步先在容器 102 验证该文件存在,PVE 内核默认开启,概率极低)。

### 2. LuCI 前端(luci-app-oaf)

**`luasrc/controller/oaf_feature.lua`**:新增 3 个透传端点:`dev_conn_list`、`get_all_users`(现有 `write_fwx_response` 模式)。

**`luasrc/view/oaf/feature.htm`** 新增第 4 个 Tab「设备连接」:

- 顶部设备下拉框(get_all_users,显示 主机名/IP/MAC),3 秒轮询连接表,弹窗打开时暂停轮询;
- 连接表每行:**勾选框 + 协议 / 目标地址:端口 / 识别应用 / Host(SNI) / 状态 / 操作**;支持全选;顶部显示已选数量与「批量学为特征」按钮;
- **学特征弹窗**(复用现有"自定义应用"编辑弹窗样式),两种目标模式:
  - 「新建应用」:名称预填(host 主域名,如 `www.douyin.com` → `douyin`),分类下拉(get_custom_feature_class_list);多选时所有勾选连接各自成为新应用的一条特征;
  - 「加入已有应用」:下拉列出当前自定义应用(来自 get_custom_feature,显示名称与已有特征数 `n/16`,已满 16 的置灰);多选时所有连接特征追加进去;
  - 特征预填规则:host 已知 → `protocol + domain`(dport 留空 = 同时匹配 SNI/HTTP Host/DNS);host 未知(纯 IP 流量)→ `protocol + dest_port` 并提示"端口特征较宽泛";domain 超 31 字符截断到主域名并提示;
  - 合并逻辑(前端 JS):按 (protocol,dest_port,domain,uri,payload) 去重;追加后超过 16 条时阻止提交并提示(服务端上限);名称重复错误原样 toast 透出;
  - 保存流程:`get_custom_feature` → 合并/追加 → `set_custom_feature {app_list:[...]}` → 刷新连接表与「自定义应用」Tab(同一数据源,自动显示)。

**翻译**:新字符串全部 `<%:...%>` 包裹并追加 `po/zh_Hans/oaf.po`(设备连接/学为特征/批量学为特征/加入已有应用/目标/协议/状态/特征数已满等),CI 自动打进 luci-i18n-oaf-zh-cn。

### 3. 构建、部署、验收

- 推送 klmmlk/OpenAppFilter → GitHub Actions 自动重编三个 ipk 并更新 `container-latest` release;
- PVE 下载新 ipk → `pct push 102` → `opkg install` → 重启 appfilter;
- 验收:① 容器内 `ubus call fwx common '{"api":"get_dev_conn_list","data":{"ip":"<设备ip>"}}'` 返回真实连接;② 「设备连接」Tab 实时刷新;③ 单条学成新应用 → 出现在自定义应用;④ 建好应用后再学第二条 → 特征数 n/16 递增;⑤ 多选 3 条 → 批量归入同一应用 → 该应用 features=3;⑥ 应用过滤规则勾选该应用 → 目标设备访问被拦;⑦ 中文翻译生效。

### 明确不做

不改内核;不新增 IP+端口匹配维度(按你确认走现有自定义应用格式);不动 ACL、rule_manager.lua 及其他页面。
